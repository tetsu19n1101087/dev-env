# 画像・アセット

## デザインツールからの書き出し

### レイヤーのエクスポートではなく元データを取る

デザインツールに配置された画像は、レイヤーとしてエクスポートすると**ツール上でのトリミング・拡縮・エフェクトが適用された状態**で出力され、元画像より劣化する。配置されている素材そのもの（raw）を取り出せば、元の解像度と品質を保てる。

### 解像度

Retina対応のため実表示サイズの2倍（@2x）で書き出す。

- **SP/PCで同じ画像を使い回す場合** — 両方のデザイン上のサイズを比べ、**大きい方を基準に2倍**（1ファイルを共用）
- **SP/PCで異なる画像を使う場合** — それぞれ各デザインのサイズの2倍で書き出し、別ファイルにする

HTMLの `width` / `height` 属性には、CSS上の表示サイズ（等倍）を書く。

### フォーマット

| 種類 | 形式 |
|---|---|
| アイコンなどベクターで表現できるもの | SVG |
| 写真 | JPG |
| 図形・文字をラスタで書き出すもの | PNG |

**WebP への変換はビルドツールに任せる**選択肢がある（後述）。その場合デザインツールからは JPG/PNG のまま書き出す。

### 命名規則

`{セクション名}-{用途}-{バリエーション}.{拡張子}` のような構造を決めておく。

- 半角小文字・ケバブケースに統一（アンダースコア・大文字・日本語・スペースを使わない）
- セクション名は `hero` `problem` `cta` など、どこの画像か一目で分かるもの
- 用途は `bg` `icon` `photo` `logo` など
- SP/PCで異なる場合のみ `-pc` / `-sp` を付ける（共用画像には付けない）
- 同用途が複数あれば `-01` `-02`（2桁ゼロ埋め、デザイン上の並び順に対応）

```
hero-bg-pc.jpg
hero-bg-sp.jpg
problem-icon-01.svg
cta-logo.svg
```

**表記を混在させない。** 英語とローマ字が混ざる、ゼロ埋めが1桁と2桁で揺れる、といった状態は後から直しにくい。

## 最適化をビルドツールに任せる

多くのフレームワークが画像最適化機能を持つ。使うと**手作業では抜けやすい項目が自動化される**。

自動でやってくれること（フレームワークによる）:

- WebP / AVIF への変換
- `width` / `height` の付与（元画像から取得）
- `loading` / `decoding` の付与

**寸法属性の自動付与は特に効く。** 手で書くと必ず抜けが出るが、自動なら構造的に保証され、CLS対策になる。

実測例（変換率の目安）:

| 元 | 変換後 | 削減 |
|---|---|---|
| JPG 30KB | WebP 8.5KB | -72% |
| PNG 104KB | WebP 34KB | -67% |

### `<source>` に `sizes` が付かないことがある

**症状:** markuplint が `The "sizes" attribute is required when the "srcset" attribute uses width descriptors`（`html-standard/srcset-sizes-constraint`）をエラーにする。

**原因:** Astro の `<Picture>` で `layout` を指定すると `srcset`（幅記述子）と `sizes` が自動生成されるが、**自動生成の `sizes` は `<img>` にしか付かず、`<source>` には付かない。** 幅記述子の `srcset` に `sizes` が無いのは HTML の仕様違反。`<Picture>` の実装は**明示された `sizes` だけ**を `<source>` に伝播する。

**確かめ方と対応:**

```bash
grep -o '<source[^>]*>' dist/index.html | grep -o 'sizes="[^"]*"'   # 何も出なければ付いていない
```

```astro
<Picture src={img} formats={['avif', 'webp']} layout="full-width" sizes="100vw" alt="" priority />
```

LCP 候補の画像には `priority` を付ける。`loading="eager"` / `decoding="sync"` / `fetchpriority="high"` がまとめて付く。1ページ1枚にとどめる。

### 配置場所が変わる

最適化機能は**ビルドツールが管理するディレクトリ配下の画像しか処理しない**。静的配信ディレクトリ（`public/` など）に置くと素通しになる。

| 形式 | 置き場所 |
|---|---|
| JPG / PNG（最適化する） | ソースディレクトリ（`src/assets/images/` など） |
| SVG（変換不要） | 静的配信ディレクトリ（`public/images/` など） |

### 出力ファイル名にハッシュが付く

`hero-bg-pc_Z13b1oc.webp` のような形になる。キャッシュ制御には有利だが、**ファイル名を固定したい運用（CMSへの個別アップロードなど）とは相性が悪い。** 納品方法を先に確認する。

### 静的配信ディレクトリの参照に注意

サブディレクトリに配置するサイト（`base` を設定している場合）、**静的配信ディレクトリのファイルは絶対パスをベタ書きすると壊れる。**

```astro
<!-- 正しい: base が付く -->
<img src={`${import.meta.env.BASE_URL}images/logo.svg`}>

<!-- 誤り: /images/logo.svg のままで404 -->
<img src="/images/logo.svg">
```

最適化機能を通さないファイルは寸法属性も自動付与されないため、手で書く。

## フォント

用途で読み込み方を変える。

- **見出しなどLCPに影響するもの** — 同期読み込み
- **本文** — 非同期読み込み（`media="print"` + `onload` など）

Webフォントを使う場合は `preconnect` を先に置く。ローカルフォントへのフォールバックスタックも必ず指定する。

## 配置とディレクトリ

セクション単位でサブディレクトリを切る。ファイル数が増えたときにフラット配置だと探しにくくなる（200近いファイルが1階層に並ぶと実質管理不能）。
