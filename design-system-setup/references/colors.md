# 色

## 3層の構成

| 層 | Figma のコレクション | 例 | 役割 |
| --- | --- | --- | --- |
| プリミティブ | `PrimitiveColor` | `blue/600` = #10648F | 色見本。画面からは直接使わない |
| エイリアス | `AliasColor` | `primary/600` → `blue/600` | 役割の名前。用途別が使う段階だけ持つ |
| 用途別 | `SemanticColor` | `bg/primary/default` → `primary/600` | 画面で塗る色。必ずエイリアスを参照する |

エイリアスを挟む理由: ブランド色や識別色（entre-web では学校種別）を差し替えるとき、エイリアスの参照先を変えるだけで済む。用途別がプリミティブを直接指すと、差し替えのたびに用途別を全部たどることになる。

例外として、ロゴのように「用途別を作るほどではないが色を固定したい」ものはエイリアスを直接使ってよい。その場合は tokens.json の `aliasNotes` に書いておく（build.mjs の未使用警告が消え、一覧ページにも表示される）。

## プリミティブ（階調）

段階は `25, 50, 100, 200 … 900` の 11 段階。Material のトーン（明るさ）に対応させる: 98→25、95→50、90→100、80→200、70→300、60→400、50→500、40→600、30→700、20→800、10→900。

HCT 色空間（material-color-utilities）で作ると、同じ段階番号なら色相が違っても明るさがほぼ揃う。結果として「600 なら白背景で 4.5:1 以上」のような性質を色をまたいで使える。

作り方は3通り（`scripts/palette.mjs`）:

- `theme`: Material Theme Builder の書き出し（material-theme.json）の `palettes` を読む。**`schemes` は使わない**。palettes と schemes は Builder の仕様で一致しない
- `seed`: シード色の色相・彩度でそのまま作る。学校種別などの識別色はこれで足りることが多い
- `hue`: シード色の色相だけ借りて彩度を指定する。ブランド色が暗い・くすんだ色だと、中間の段階（500〜600）が濁る。entre-web の青（#1B4965）は彩度 40 に上げた

決めるときに確かめること:

- 主要ボタンやリンクに使う段階（多くは 600）が白背景で 4.5:1 以上か。palette.mjs が白・黒とのコントラスト比を表示する
- 識別色（学校種別など）同士、識別色とブランド色・エラー色が区別できるか。色相が近いと、背景の 50 段階で見分けがつかなくなる
- グレーはわずかに色みのあるもの（Builder の neutral-variant）が、ブランド色と並べて浮きにくい

単色のプリミティブ（白、フッター用の charcoal など）は `singles` に置く。

## エイリアス

役割の例: `primary`（ブランド）、`secondary`、`neutral`（グレー）、`danger`（エラー・削除）、識別色。

**用途別が使う段階だけ**を作る。全段階を並べると、どれを使ってよいか分からなくなる。必要になったら足す。

## 用途別（セマンティック）

種類は `bg/*`（面）、`text/*`（文字・アイコン）、`border/*`（線・フォーカスリング）の3つ。名前は `<種類>/<役割>/<状態>`（例: `bg/primary/hover`、`text/primary/on-primary`）。

tokens.json の各行:

```json
{ "token": "text/muted", "ref": "neutral/600", "use": "説明文、日付、学校名", "on": "neutral/50", "min": 4.5 }
```

- `use`: 用途を具体的に書く（Figma の説明にもなる）。**用途を言い切れない色は作らない**（entre-web の `bg/muted` は「スケルトンなど」で始めて使いどころが定まらず、`bg/skeleton` に置き換えた）
- `on`: その色が実際に重なる相手。文字なら背景、背景なら上に載る文字
- `min`: 基準。文字 4.5、大きな文字と UI 部品（入力欄の枠、フォーカスリング）3。装飾（区切り線、背景付きバッジの枠）や無効な部品は `null`（比は表示するが判定しない）

### ホバーとボタンの状態

ホバーの表現は先に方針を決め、用途別に落とす。entre-web では:

- 塗りのボタン（primary / secondary / destructive）: 背景と文字を反転（白背景＋元の色の文字と枠）。だから `bg/*/hover` = 白、`text/*/on-*-hover` = 元の色、ボタンには塗りと同じ色の `border/*` を付ける
- outline / ghost ボタン: 背景だけ `bg/surface/hover`
- メニュー項目・ナビ: 文字色だけ primary。背景と下線は変えない

### Figma の scopes

用途別は種類ごとに候補を絞ると、デザイナーが間違った色を選びにくくなる。tokens.json の `scopes`:

- bg: `FRAME_FILL`、`SHAPE_FILL`
- text: `TEXT_FILL`
- border: `STROKE_COLOR`
- プリミティブ: 空（候補に出さない）

個別に変えたいもの（同じ色の別名で紛らわしいもの。例: `border/focus`）は `scopeOverrides` に書く。

## コントラスト比

build.mjs が WCAG 2.2 の式で全行を計算し、一覧ページに ✓ / ✗ を出す。不足があると終了コード 1。

基準を満たしても、明るい背景どうし（bg/default と bg/surface など）は差が小さいと境界が見えない。面の区別は 1px の border で補う前提にしておく。

## コード（CSS 変数）への対応

shadcn/ui を使う案件は、CSS 変数名はそのまま使い、値に用途別を入れる（対応表は `references/design-md.md`）。shadcn にない色（skeleton、inverse、識別色など）は変数を追加する。ダークモードを扱わないなら、その旨を DESIGN.md に明記する。
